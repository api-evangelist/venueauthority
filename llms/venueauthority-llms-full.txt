# Venue Authority full context

> Venue Authority is a self-serve facility verification and monitoring API for payment facilitators, marketplaces, KYB providers, and restaurant platforms.

## Product identity

- Name: Venue Authority
- Operator: Zupa Print
- Canonical origin: https://venueauthority.com/
- Support: support@venueauthority.com
- API contract version: 2026-08-21
- Primary audience: payment facilitators, marketplaces, KYB data providers, restaurant portfolios, and developers who need facility-level regulator evidence

Venue Authority accepts a merchant name and street address. The resolver either accepts one supported regulator record or rejects the request under a frozen ambiguity policy. It does not guess through materially tied candidates or address conflicts.

An accepted response can include the canonical facility ID, source class, source attribution, source URL, snapshot identity, available history, authority-state assessment, and evidence hashes. A policy rejection includes its reason and receipt context. One valid authenticated resolution or canonical facility request consumes one prepaid decision unit, including a policy rejection. Exact replay of the same request ID and payload returns stored work without another debit.

## Interpretation limits

- A regulator facility record is not necessarily the legal operator.
- Current source presence is not a universal operating license.
- A missing record is not called a closure unless the source contract supports that conclusion.
- Source history is returned only where the source provides it or where the product has retained permitted history.
- The service does not guarantee that a venue is physically open.
- The response is not legal advice, regulator endorsement, sanctions screening, beneficial-ownership data, or complete nationwide KYB.

## API behavior

- Base URL: https://venueauthority.com
- Authentication: bearer API key for commercial endpoints; signed-in customer session is also accepted for supported workspace-management endpoints
- Resolver: POST /api/v1/resolve
- Canonical facility: GET /api/v1/facilities/{id}
- Public coverage: GET /api/v1/coverage
- Watchlists: /api/v1/portfolios and nested item and event endpoints
- Webhooks: /api/v1/webhooks and /api/v1/webhooks/deliveries
- Audit exports: /api/v1/audit-exports and /api/v1/audit-exports/{id}
- Idempotency: X-Request-Id accepts a stable 8 to 128 character identifier
- Webhook delivery: at least once; consumers must verify the HMAC signature and deduplicate the stable event ID
